# Cube Minimalist Forum（Cube 极简论坛）

纯文字 · 极简 · 零依赖的轻量论坛系统。
**纯 PHP 实现，不使用数据库（文件存储），无 Composer、无前端框架、无任何第三方库。**

- 程序本体 ≤ 10MB（实际仅约 0.1MB）
- 解压上传即用，首次访问自动进入安装向导
- 游客可读，注册后可发言；AI 自动审核举报内容，支持申诉与人工复核
- **后台「更新升级」：上传更新包 zip 即可升级，无需重装、数据不丢**
- **全员操作日志：注册 / 登录 / 发帖 / 回复 / 点赞 / 举报 / 后台操作均有记录，后台可查，一键导出 TXT**
- **恶意爬虫与异常自动检测：伪造蜘蛛 PTR 验证 / 未知爬虫 UA / 敏感文件探测 / 伪造 CF 头 / 超长请求等九条策略规则自动评分封禁**
- **攻击邮件告警：多次攻击自动发信全部管理员（含来源 IP Top5 与处置建议），带冷却防轰炸**
- **服务器性能监控：CPU / 内存 / 磁盘动态图标实时卡 + 存储占用进度条，存储超限自动邮件告警管理员**
- **前台实时刷新：在线人数 / 未读通知 / 新帖新回复提示自动更新，页面切后台自动暂停省流量**
- **环境自检：后台可查看 data/ 可写性、关键函数可用性与 error.log，快速定位主机环境问题**
- **页脚可自定义**（后台「主题」页，留空显示默认文案）
- 响应式设计 + 深色模式 + 主题色可配置
- 支持 PHP 7.4 ~ 8.x，无需任何特殊扩展（用到 curl 时会自动回退）

## 一、部署（三步）

1. **上传解压**：将整个 zip 包上传到服务器网站目录（如 `public_html/`），解压。
   - 可以解压到网站根目录直接作为整站；
   - 也可以解压为子目录（如 `/forum/`），通过 `https://你的域名/forum/` 访问。
2. **目录权限**：确保 `data/` 目录可写（FTP 中一般默认即可；如不可写，将 `data/` 权限设为 `755` 或 `775`）。
3. **访问安装**：浏览器打开站点地址，自动进入安装向导，按 6 步完成安装。

> 环境要求：PHP 7.4+（推荐 8.0+），Apache 或 nginx，无需 MySQL / Redis / cron / 命令行。

### 性能与并发（v1.16.0 起内置）

- **多进程并发**：如用 PHP 内置服务器跑（`php -S`），请设置 worker 数，即可同时响应 15+ 人（此前单进程一次只能服务一人，有人发帖触发 AI 审核时其他人会明显变慢）：

  ```bash
  PHP_CLI_SERVER_WORKERS=15 php -S 0.0.0.0:8080 -t /path/to/forum
  ```

  Apache / nginx + php-fpm 天然多进程，无需此步；
- **输出 gzip 压缩**：页面 HTML 传输体积自动压缩约 60%～80%（客户端不支持时自动降级为不压缩），配合 Cloudflare 等 CDN 效果更好；
- **静态资源强缓存（v1.17.0）**：CSS / JS / 图标由程序出响应，带一年期 immutable 缓存头与 ETag/304，二次访问几乎零下载；
- **数据文件透明压缩**：数据文件以 gzip 格式落盘（中文内容体积约省一半以上），旧数据读取完全兼容，后台「系统」页可一键把存量明文数据转为压缩格式；
- **日志与备份压缩（v1.17.0）**：日志文件每天日切自动压缩（约 5:1～10:1），备份 zip 采用 deflate 压缩（体积 -50%～-80%），读侧自动兼容新旧格式；
- **请求级数据缓存（v1.17.0）**：页面内重复的文件读自动去重（用户表 / 板块表 / 帖子文件），列表页渲染更快；
- **AI 审核不再阻塞页面**：发帖预检改为响应后异步执行，发帖立即返回，AI 审核在后台完成（违规仍会自动隐藏并通知申诉）；收尾阶段先释放会话锁再跑 AI，后续页面请求不再被拖慢。

### nginx 用户额外一步

Apache 用户已内置 `.htaccess` 保护，nginx 用户需在站点配置中手动禁止访问数据与源码目录：

```nginx
location ~ ^/(data|src)/ { deny all; }
```

### 安装完成后

- 安装向导会在 `data/lock/install.lock` 留下安装锁，重复访问 install.php 会被拒绝；
- **强烈建议通过 FTP 删除 `install.php`**，彻底杜绝重复安装风险。

## 三、邮件配置（SMTP）

论坛使用邮箱验证码完成「注册 / 修改密码 / 找回密码」。

以 **QQ 邮箱** 为例：

1. 登录 QQ 邮箱网页版 → 设置 → 账户 → 开启「SMTP 服务」；
2. 按提示获取 **授权码**（注意：是授权码，不是 QQ 密码）；
3. 后台「邮件」页填写：
   - SMTP 主机：`smtp.qq.com`
   - SMTP 端口：`465`（SSL，推荐）或 `587`（自动 STARTTLS）
   - 发信邮箱：你的 QQ 邮箱
   - 授权码：上一步获取的授权码
4. 点击「测试发信」，填入一个收件邮箱当场验证。

163 邮箱：`smtp.163.com:465`；Gmail：`smtp.gmail.com:465`（需应用专用密码）。

## 四、AI 配置（举报内容自动审核）

任何 **OpenAI 兼容接口** 均可，后台「AI」页支持**自由添加多个 API 密钥与模型**（每个模型：备注名称 / API 地址 / 密钥 / 模型名 / 启停 / 顺序）：

- **API 地址**：以下三种写法都支持
  - `https://api.openai.com`（根地址）
  - `https://api.example.com/v1`
  - `https://api.example.com/v1/chat/completions`（完整地址）
- **API 密钥**：服务商提供的 Key
- **模型名称**：如 `gpt-4o-mini`、`glm-4-flash`、`deepseek-chat` 等
- **自动切换阈值**：某模型连续失败达到该次数（默认 3，可调 1-20）后，后续审核自动换下一个模型
- **单模型重试次数**：同一模型单次审核内的 HTTP 重试次数（默认 3）
- **全火力全开**：勾选后每条内容同时交给**所有启用的模型**一起审核（任一判定违规即违规，全部无问题才放行）
- **严全面模式（AI 全自主值守）**：①发帖 AI 预检——新帖 / 回复发布后立即主动审核，违规自动隐藏可申诉；②AI 自主管理——AI 按间隔自主巡逻，自主封禁恶意 IP / 解除误封 / 邮件警报管理员（全部白名单校验、限量、留痕、可撤销）；③可选常驻巡逻器 `php daemon.php`（7×24 值守，无常驻条件自动退回访客触发模式），无风险事件时零消耗跳过
- **审核严格程度**：宽松 / 标准（默认）/ 严格三档，控制「拿不准时怎么判」；审核提示词主体由程序内置固定，后台仅可切换尺度，保证审核口径稳定可预期，保存后立即生效

多模型机制：

- 审核按模型列表顺序调用；某模型连续失败达到阈值后自动排到队尾，后续审核优先使用其他模型（状态徽章实时可见：主力 / 备用 / 连续失败 N 次 / 已切换 / 已停用）；
- 单次审核内前序模型失败也会继续尝试其余模型，**所有模型都失败才转人工审核**；成功的模型自动成为下次「主力」并清零失败计数，故障模型恢复后自动重新入列；
- 列表顺序即优先级，可上移 / 下移调整；每个模型可单独「测试」，失败计数支持手动「清零」立即恢复。

审核机制：

1. 用户举报内容后，**内容立即隐藏**，进入 AI 待审队列（先进先出）；
2. AI **每次只处理队列中的一条**（随论坛访问自动触发，避免触发速率限制；后台也可手动「立即审核一条」）；
3. AI 判定有问题：内容保持隐藏，通知被举报人，**允许申诉**；
4. AI 判定没问题：自动恢复展示，并通知举报人；
5. 被举报人在「公告与通知 → 我的通知」中点击**申诉** → 提示「已发送至管理员」→ 进入人工待审列表，且该内容**永久不能再被举报**；
6. 所有模型重试后仍失败：内容保持隐藏，通知管理员到后台处理；
7. 管理员人工审核：有问题 → 删除（自动通知作者）；没问题 → 恢复（提示「二次审核未检测到问题，已恢复」）。

## 五·一·五、绑定域名（限制特定域名访问）

后台「基本 → 绑定域名（授权域名）」，用于防止他人把域名恶意解析到你的主机（蹭流量、搜索引擎误收录镜像站）：

- **留空 = 不限制**（默认，兼容一切环境）；
- 填写后，仅允许列表内的域名访问论坛；其他域名（含 IP 直连）访问一律 **301 永久跳转**到第一个授权域名，原路径原样保留，搜索引擎权重自动归拢到正版域名；
- 多个域名用逗号分隔；**带 www 与不带 www 是两个域名**（如 `forum.example.com,www.example.com`），需要分别填写；
- 保存时自动清洗：填了 `https://forum.com:8080/` 也会被规范化为 `forum.com`；
- **自救**：万一把域名写错导致无法访问，通过 FTP 打开 `data/config.php` 删掉 `bind_domains` 一行（或清空其值）即可恢复。

## 五·二、更新升级（免重装）

当开发者发布新版本时，会同时提供：

1. **完整安装包**（全新部署用）；
2. **通用更新包**（如 `forum-update-any-to-1.10.0.zip`）：**v1.1.0 及以上的任意版本均可直接上传这一个包升级到最新版**，无需逐版本中间升级；
3. （历史）专用升级包（如 `forum-update-1.4.1-to-1.5.0.zip`）：v1.6.0 起已被通用更新包取代，仅作历史存档。

更新包含全部程序文件，更新器只要求目标版本高于当前版本（不限制来源版本），因此任意旧版本（v1.1.0+）一步到位；升级时自动补齐新版本新增的配置项（不覆盖已有配置，可重复上传、幂等安全）。

升级方法：后台「更新升级」→ 选择更新包 zip → 「上传并安装更新」。程序会自动：

1. 把当前程序文件备份到 `data/backup/pre-update-*.zip`（保留最近 3 份，可在线下载）；
2. 按 `update.json` 清单覆盖变更文件（**绝不触碰 `data/` 数据目录与 install.php**）；
3. 执行 `update/migrate.php` 数据迁移脚本（如有）；
4. 版本号前进，页脚与「系统」页同步显示；全过程记录在操作日志。

> 若服务器 php.ini 限制了上传大小，请调大 `upload_max_filesize` / `post_max_size`（更新包通常只有几十 KB）。也可以解压更新包后用 FTP 直接覆盖同名文件，效果等同。

## 五·三、操作日志

- 记录范围（含游客相关行为）：注册 / 登录（含失败，带 IP）/ 退出 / 发验证码 / 改密 / 改资料 / 发帖 / 回复 / 删帖 / 删回复 / 点赞 / 举报 / 申诉，以及**全部后台操作**（设置、板块、用户、内容、审核、公告、主题、备份、更新）；AI 审核结论也会以「系统」身份记录。
- **动作分布图表**：日志页按日期筛选时，同步展示当日「动作分布 Top 10」排行图（纯手写图表，无第三方库）。
- 存储：按天分文件存于 `data/logs/log-YYYY-MM-DD.php`，每条记录含时间 / 用户 / 动作 / 详情 / IP，守卫前缀保护，无法被 Web 直接访问。
- 保留策略：默认 90 天（后台可改，0 = 永久），每天自动清理；日志总量上限 20MB，超出从最旧删起（保护 100MB 存储空间）。
- 页面访问日志默认关闭（会产生大量记录），需要时在「日志」页开启，开启后游客浏览也会记录。

## 五·四、服务器监控与存储告警

后台「监控」页提供：

- **实时资源卡（动态图标）**：CPU / 内存 / 磁盘三张卡片，环形进度 + 动画图标 + 每 5 秒自动刷新；读数分三级变色（正常 / ≥60% 琥珀 / ≥85% 红）。CPU 与内存读数来自系统接口（/proc），仅 Linux 主机可用，其他环境显示“—”不影响其他功能；
- **存储占用**：程序本体 + 数据目录合计，进度条直观展示（配额默认 100MB，可在监控页查看）；附**存储构成明细图**（程序文件 / 帖子 / 回复 / 日志 / 备份 / 会话 / 其他，纯 CSS 手写图表）；
- **服务器信息**：PHP 版本与 SAPI、系统负载（1/5/15 分钟）、磁盘剩余空间、内存 / 执行时间 / 上传限制、curl 与 mbstring 可用性；
- **内容规模**：帖子 / 有回复的帖 / 用户 / 操作日志体积 / 备份文件数 / 当前在线；
- **存储告警**：总占用超过阈值（默认 **95MB**）时，自动给全部管理员发送告警邮件，内容包括占用明细与清理建议（清理日志、删除旧备份等）。检查随论坛访问进行（每小时至多一次），持续超限时每 6 小时提醒一次，回落到阈值下后自动重置；也可在监控页手动「发送测试告警邮件」验证链路。

> 告警邮件通过后台「邮件」中配置的 SMTP 发送；未配置邮件时监控页仍可正常查看，只是无法发信。

## 五·六、安全防护（防火墙）

后台「安全防护」页，v1.8.0 起内置五道防线（自上而下依次执行，**已登录管理员与白名单 IP 不受任何拦截**）：

1. **IP 白名单**：支持单 IP 与网段（`203.0.113.7, 198.51.100.0/24`），命中后跳过一切拦截。设置页会显示你当前 IP，建议先加白再配置；若站点在反向代理 / CDN 后，勾选「信任 X-Forwarded-For」（直接暴露的服务器勿开，防伪造头绕过）。
2. **封禁名单**：手动封禁（30 分钟 ~ 30 天或永久，可填理由，支持封网段）+ 自动策略封禁。封禁命中返回 403 说明页（含理由与解除时间）；后台一键解封。
3. **危险 IP 库（威胁情报）**：内置 Emerging Threats、Abuse.ch Feodo、Blackbook 三个公开源（可开关），支持自定义源 URL 与粘贴 / 上传黑名单导入；自动同步默认每 24 小时（管理员打开安全页时惰性触发，无需 cron），也可「立即同步」。命中即 403。误判可加入白名单。
4. **限流**：每 IP 每分钟请求上限（默认 60），超限返回 429；可选「超限自动临时封禁」。登录管理员不受限。
5. **自动策略机器人**：九条内置规则（空 UA +40 / 脚本 UA +50 / 敏感路径探测 +80 / 注入特征 +90 / 伪造搜索引擎蜘蛛 +80（PTR 反解验证，防冒充 Googlebot / Baiduspider 等）/ 未知爬虫 UA +25 / 敏感文件探测 +50 / 伪造 CF 头 +50 / 超长请求 +30）按 10 分钟滑动窗口累计风险分，达到阈值（默认 100）自动临时封禁（默认 24h）；高频 404 计入评分；搜索引擎蜘蛛自动放行（真蜘蛛 IP 另有 PTR 验证，伪造必被识破）。支持**自定义规则**（UA / 路径 / 查询参数 × 文本包含 / 正则 × 加分 / 直接封禁）。

**攻击告警（v1.9.0）**：10 分钟窗口内防火墙拦截（限流 / 封禁名单 / 危险 IP 库 / 自动封禁均计入）达到阈值（默认 20 次，可配）时，自动给全部管理员邮箱发送告警：今日拦截 / 请求统计、事件最多的来源 IP Top5、最近事件摘要与处置建议；带冷却（默认 30 分钟）防轰炸，发信在响应完成后进行（不拖慢站点）；可一键发送测试邮件验证链路。

**Cloudflare CDN 适配（v1.8.1）**：接入 Cloudflare 代理后**零配置自动生效**——程序内置 CF 官方网段（IPv4 15 条 + IPv6 7 条），仅当 TCP 对端确属 Cloudflare 边缘时才信任 `CF-Connecting-IP` 取真实访客 IP，直连伪造无效。限流 / 封禁 / 统计 / 归属地全部基于真实 IP，避免「同节点访客被集体限流 / 自动封禁误封 CF 节点导致整站 403」。后台「安全防护」页有**实时链路诊断卡**（直连 / Cloudflare / 本机反代套 CF / 经代理 XFF）与推荐配置清单；Cloudflare 套在宝塔等本机反代之前时，勾选「信任 X-Forwarded-For」会自动优先用更可信的 CF 头。

**访问统计**：自动统计每个 IP 的请求数、404 数、最近活动与 UA（7 天不活跃自动清理），支持 ip-api.com 免费批量查询 IP 归属地（国家 / 省 / 市 / 运营商，缓存 30 天），一键封禁 / 解封。

**防火墙日志**：独立于操作日志（`data/logs/fw-日期.php`），记录每次拦截 / 封禁 / 评分 / 限流的 IP、UA、请求、命中规则与风险分；每日至多 2000 条防刷爆，保留天数（默认 14）与总量（≤5MB）自动管理；支持按日期 / IP 筛选与一键清空。

> 主机需能访问外网才能在线同步威胁情报源（cURL 或 file_get_contents 任一可用即可）；无外网时可手动导入黑名单文本，或仅使用内置策略规则。

## 六、数据与备份

- 全部数据以 JSON 文件存于 `data/` 目录，无数据库：
  - `config.php` 站点配置；`users.php` 用户；`boards.php` 板块
  - `threads/index.php` 帖子索引（列表页只读索引，高效）；`threads/t{ID}.php` 帖子正文；`replies/t{ID}.php` 每帖回复独立文件
  - `reports.php` 举报；`queue.php` AI 队列；`announcements.php` 公告；`notify/` 用户通知；`updates.php` 更新历史；`logs/` 操作日志与防火墙日志
  - 防火墙（v1.8.0）：`fw_bans.php` 封禁名单；`fw_rules.php` 自定义规则；`fw_intel.php` 危险 IP 库；`fw_state.php` 访问统计 / 限流计数 / 攻击告警窗口 / 蜘蛛 PTR 验证缓存；`fw_geo.php` 归属地缓存
- 数据文件带守卫前缀且目录有 `.htaccess` 双重保护，直接 Web 访问只会得到 Forbidden；
- 所有写入均为 **加锁 + 临时文件 + 原子 rename**，杜绝并发写坏；
- **备份**：后台「系统 → 一键备份数据目录」生成 zip（内置零依赖 ZIP 生成器，不依赖 ZipArchive 扩展），保留最近 5 份，可在线下载。迁移 = 备份 + 恢复，或直接 FTP 打包 `data/` 目录。

## 七、安全设计

- 密码 `password_hash` 哈希存储；会话 httponly + SameSite；全站 CSRF 校验
- 验证码：5 分钟有效、同邮箱 60 秒限发、错 5 次作废、一次性使用
- 防灌水：发帖 / 回复间隔限制；禁言与封号
- 输出全站转义，Markdown 渲染前整体转义（天然防 XSS），链接仅允许 http(s)，图片仅允许 https 外链（懒加载 + 不带来源引用）
- 「保持登录」使用独立随机 Token（哈希落盘，可随时失效）
- **防火墙（v1.8.0）**：白名单 / 封禁名单 / 危险 IP 威胁情报库 / 限流 / 自动策略机器人五道防线（见「五·六」）
- **Cloudflare 真实 IP 识别（v1.8.1）**：仅当 TCP 对端确属 CF 官方网段（内置 v4+v6 22 条）才信任 `CF-Connecting-IP`，伪造头无效
- **安全响应头**：nosniff、同源框架嵌入保护、Referrer-Policy、Permissions-Policy；HTTPS 下会话 Cookie 自动附加 Secure
- **data/ 目录 .htaccess 全目录拒绝访问**（含运行错误日志与防火墙日志），数据文件另有守卫前缀双重保护
- robots.txt 限制爬虫频率与后台页面

## 八、常见问题

**Q：忘记管理员密码？**
用管理员的注册邮箱走登录页「忘记密码」流程即可（需邮件配置可用）。

**Q：安装向导提示数据目录不可写？**
FTP 中将 `data/` 目录权限改为 `755`（或 `775` / `777`，视主机策略）。

**Q：发帖报「目录不可写（需要写权限）」？**
1. 先到后台「监控 → 环境自检」点「**一键修复目录权限**」（v1.4.0 起支持自动救回属主不对的非空目录，数据不丢）；
2. 若仍不可写，通过 FTP / 主机面板将 `data/` 及其全部子目录与文件的权限设为 `755` 或 `775`（确保 PHP 运行账号拥有写权限）；
3. `data/` 下若有 `.broken-*` 暂存目录（自愈时让位的旧目录，数据已搬回），确认无需找回后可删除。

**Q：磁盘未满仍提示写入失败？**
多为目录属主 / 权限问题而非磁盘空间：FTP 解压产生的目录属主是 FTP 账号，PHP 运行账号（如 www-data）可能无权写入。按上一条先一键修复或改权限；也可到「监控 → 环境自检」查看具体哪个目录不可写与 error.log 详情。

**Q：想迁移或重置论坛？**
迁移：打包 `data/` 目录随程序一起带走。重置：删除 `data/` 下全部内容（保留 `.htaccess`），重新访问站点即可重新安装。

**Q：验证码收不到？**
检查后台邮件配置并使用「测试发信」；请收件人检查垃圾箱；部分主机封禁 25/465 端口，可联系服务商或更换端口。

# 更新日志 · Cube Minimalist Forum

## v1.8.2（2026-10-04）

### 修复（两个重要 bug，感谢用户反馈）
- **修复「保存总开关会把其他防护设置打回默认」**：v1.8.0/1.8.1 中总览页「防火墙总开关」小表单与「限流与自动策略」大表单共用同一个保存接口，且所有字段都按 POST 内容覆盖——只提交总开关时，限流、自动策略、内置规则、IP 白名单、Cloudflare 适配等全部被重置为默认值（限流关、策略关、白名单清空、CF 适配关）。现拆分为独立保存接口：
  - 「防火墙总开关」表单现在**只改动总开关本身**，其余设置分毫不动；
  - 「限流与自动策略」大表单保存时自动携带当前总开关状态，**不再把总开关意外关闭**；
  - 保存接口对未提交的字段一律回退当前值，从根上杜绝同类「缺字段即重置」问题
- **修复「IP 归属地全部显示未知 / 归属地未查询」**：旧版归属地批量查询把**查询失败的行也缓存成空条目并保留 30 天**（触发条件：ip-api.com 免费接口限流 45 次/分钟、保留 IP 段、服务器无法访问外网等），一旦触发，这些 IP 永久显示「未知」且无法自愈。现全面重构：
  - 失败的行**不再写入缓存**，改为进入重试节流表（30 分钟后点查询自动重试，全部失败 1 小时后重试），不会留下错误的「未知」记录
  - 升级后自动**自愈**：历史空条目视为「未查询」，重新点「查询本页归属地」即可补上真实数据
  - 传输通道从仅支持 cURL 扩展为 **cURL / file_get_contents 双通道**，没有 cURL 的主机也能查询
  - 主源 ip-api.com 整体连不上时，**自动切换备用源 ipwho.is**（HTTPS、免 key），并在按钮旁显示诊断提示（「主源暂不可用，已用备用源查到 N 个」/「数据源暂时连不上，请检查主机外网连通性」）

### 升级说明
- 更新包内含一次性数据迁移：**自动检测并修复**曾被上述 bug 重置的防护配置（限流 / 自动策略 / 内置规则 / CF 适配恢复为推荐的默认开启状态，总开关保持你当前的选择；IP 白名单无法自动恢复，如之前配置过请到安全防护页重新填写）
- 升级后到「安全防护 → 访问统计」点一次「查询本页归属地」，历史「未知 / 未查询」的 IP 会重新查询并显示真实归属地

## v1.8.1（2026-10-04）

### 新增（Cloudflare CDN 适配）
- **自动识别 Cloudflare**：内置 Cloudflare 官方网段（IPv4 15 条 + IPv6 7 条，来自 cloudflare.com/ips），当请求的 TCP 对端确属 CF 边缘节点时，自动从 `CF-Connecting-IP` 头取真实访客 IP（其次 `CF-Connecting-IPv6`，再退 `X-Forwarded-For`）——**零配置，装上即生效**
- **防伪造设计**：仅当 TCP 对端（`REMOTE_ADDR`）确属 Cloudflare 官方网段才信任 `CF-Connecting-IP`；直连源站的伪造请求该头一律忽略，无法借机绕过限流或冒充他人 IP
- **全链路真实 IP**：限流、自动封禁、访问统计、404 扫描计数、IP 归属地查询、防火墙日志、操作日志记录的 IP 全部切换为真实访客 IP，修复接入 CDN 后「同一 CF 节点的所有访客被集体限流 / 自动封禁误封 Cloudflare 节点导致整站 403」的严重问题
- **后台「真实 IP 识别」诊断卡**：安全防护页实时显示当前链路类型（直连 / Cloudflare CDN / Cloudflare → 本机反代 / 经代理 XFF）、TCP 对端、各转发头与最终识别 IP，一眼核验 CDN 接入是否生效
- **新增配置项**（安全防护页，均有安全默认值）：
  - `Cloudflare CDN 适配`：默认开启；未使用 Cloudflare 的站点此开关无任何影响
  - `Cloudflare 网段覆盖`：留空使用内置官方网段；CF 官方未来调整网段时可自行填入覆盖
- **本机反代套 CF 场景增强**：开启「信任 X-Forwarded-For」后若同时存在 `CF-Connecting-IP`（Cloudflare 套在宝塔等本机反代之前，该头会原样透传），自动优先取之——XFF 首段可被客户端伪造，CF 头由边缘覆写更可信
- **IPv6 网段匹配工具**：新增纯 PHP IPv6 CIDR 匹配（位运算实现，零依赖），供 Cloudflare 网段识别使用；原有 IPv4 封禁 / 白名单逻辑不受影响
- **Cloudflare 接入推荐配置清单**：后台「安全防护」页可展开查看（SSL/TLS 完全严格、勿缓存 HTML、Rocket Loader 建议关闭等六条）

### 兼容性说明
- 未使用任何 CDN / 反代的站点：行为与 v1.8.0 完全一致（默认 `REMOTE_ADDR`），无需任何调整
- 升级前若已在 CF 代理状态下产生过自动封禁，名单中可能残留 CF 节点 IP 条目——升级后这些条目不再匹配真实 IP，可到后台「安全防护 → 封禁」自行清理

## v1.8.0（2026-10-04）

### 新增（防火墙与安全防护中心）
- **后台新增「安全防护」标签页**，五道防线全部可配置，纯 PHP / 文件存储 / 零依赖实现：
  1. **IP 白名单**：管理员自填（逗号 / 换行分隔，支持网段 `1.2.3.0/24`），命中后跳过一切拦截；设置页显示你当前 IP，方便先加白再配置，避免把自己拦在外面
  2. **自动封禁危险 IP（威胁情报库）**：内置三个公开威胁情报源（Emerging Threats 恶意 IP 列表、Abuse.ch Feodo C&C、Blackbook），可开关；支持添加自定义源 URL；也支持把黑名单文本**粘贴或上传 .txt 导入**（每行一个 IP / CIDR / IP 区间）。库同步支持手动「立即同步」与自动同步（默认每 24 小时，管理员打开安全页时惰性触发，无需 cron）。匹配采用哈希精确命中 + 网段二分查找，十万级条目毫秒级响应；IPv6 暂不参与匹配
  3. **访问统计与限流**：自动统计每个 IP 的请求次数、404 次数、最近活动时间与 UA（7 天不活跃自动清理），展示 IP 归属地（国家 / 省 / 市 / 运营商，通过 ip-api.com 免费批量接口查询并缓存 30 天，页内一键批量查询）；限流按「每 IP 每分钟请求上限」配置（默认 60），超限返回 429，可配「超限自动临时封禁」分钟数
  4. **内置自动策略机器人**：内置四条策略规则（空 UA +40 分、脚本 / 攻击工具 UA +50 分、敏感路径探测 wp-admin/.env 等 +80 分、SQL 注入 / XSS / 目录穿越特征 +90 分），按 **10 分钟滑动窗口**累计风险分，达到阈值（默认 100）自动临时封禁（默认 24 小时）；高频 404 扫描也计入评分；搜索引擎蜘蛛 UA 自动放行防误伤；管理员可**自定义规则**（按 UA / 路径 / 查询参数，支持纯文本包含或正则，命中加分或直接封禁），规则可启停删除
  5. **手动封禁与详细日志**：支持手动封禁单 IP 或网段（30 分钟～30 天或永久），填写封禁理由；一键解封；**防火墙事件日志**独立存放（`data/logs/fw-日期.php`），完整记录拦截 / 封禁 / 评分 / 限流事件的 IP、UA、请求方法与路径、命中规则、风险分，支持按日期与 IP 筛选分页查看、一键清空；每日至多 2000 条防恶意刷爆配额，保留天数与总量（≤5MB）自动管理
- **防误伤设计**：已登录管理员不受任何拦截；白名单优先级最高；所有自动封禁均可后台手动解除
- **防护总览卡片**：今日 / 昨日请求与拦截数、今日新增封禁、封禁名单数、危险库条数一目了然

### 修复
- **主题色「换不了颜色」**：修复自定义取色器总是携带旧颜色并无条件覆盖色板选择的问题——此前无论点色板哪个颜色，保存的都是取色器里的旧值。现在仅当用户真的改动了取色器（与当前已保存色不同）才采用自定义色；只修改深色模式 / 页脚等其他设置时不再把颜色重置回默认
- **限流与统计的跨请求失效问题**（开发期发现）：防火墙计数改为与在线统计相同的「读快照 → 修改 → 原子落盘」模式，确保每请求间隔下限流计数、风险分窗口、404 扫描计数跨请求持续累计

### 加固（整体安全性提升）
- **安全响应头**：全部页面输出 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`（防点击劫持）、`Referrer-Policy: strict-origin-when-cross-origin`（防外链泄露完整路径）、`Permissions-Policy`（禁用摄像头 / 麦克风 / 定位）
- **会话 Cookie 加固**：HTTPS 环境自动附加 `Secure` 标志（防降级窃听）；已有 `HttpOnly` + `SameSite=Lax` 保持不变
- **运行错误日志移入受保护目录**：`data/error.log` → `data/logs/error.log`（受 `data/.htaccess` 全目录拒绝访问保护），避免被 Web 直接读取泄露服务器路径信息
- 注入特征检测兼容 URL 编码形式（`%20`、`%3C`、`%3D` 等），绕过难度更高

### 开发与质量
- 新增防火墙单元测试 52 项（IP / CIDR 工具、白名单、黑名单解析、封禁与解封、限流、评分策略、危险库二分匹配、自定义规则、内置正则防误伤、主题色修复回归）全部通过
- 端到端实测（php -S 真实 HTTP 环境）五道防线全部按预期拦截 / 放行

## v1.7.0（2026-10-04）

- 安全边界不变：全部内容仍先整体 HTML 转义再渲染（天然防 XSS）；图片仅 https 外链、懒加载、不带引用；代码 / 链接 / 图片一律占位符保护，语法规则互不干扰

## v1.4.1（2026-10-04）

- **监控页环形进度渲染成一团黑色实心圆**：SVG 圆形的默认填充色是黑色，此前「不填充」完全依赖样式表中的 `.ring-bg/.ring-fg { fill:none }` 规则；而样式表引用地址不带版本号，浏览器会长期使用缓存的旧文件——升级程序后一旦样式表还是旧缓存（或 FTP 覆盖时未更新成功），环形就会退化成纯黑色圆形。现 `fill="none"` 直接内联进 SVG 标签（内联属性优先级低于样式表，主题色与深色模式不受任何影响），**无论样式表新旧都不会再出现黑圆**；同时样式表与脚本引用统一加版本号参数（`?v=版本号`），升级后浏览器立即拉取新资源，杜绝各类「升级后样式错乱」

### 修复（个人主页帖子数与列表不符）
- **个人主页显示「发了 N 个帖子」，下方列表却是空的**：帖子数此前读用户档案里的计数器字段，该计数在历史版本静默写失败（发帖「假成功」）或删帖边界场景下会虚高。现帖子数改为**直接读取数据资源**（`threads/index.php` 帖子索引）实时统计，与下方「TA 的帖子」列表完全同源，数字与列表永远一致

## v1.4.0（2026-10-04）

### 修复（发帖失败专项 · 目录自愈能力升级）
- **「目录不可写」自愈能力升级——整体搬移重建**：通过 FTP / 主机面板解压或上传产生的数据子目录（如 `data/threads/`），属主往往不属于 PHP 运行账号；当目录非空时（帖子索引就在里面），此前 `chmod`（非属主失败）与「空目录重建」（非空失败）都无法救回，表现为发帖报「threads/index.php：目录不可写」。现利用 POSIX `rename` 只依赖**父目录**写权限的特性：把旧目录整体改名为 `data/.broken-xxx` 让位 → 原位重建属主正确的目录 → 将旧目录内文件逐个读出写回，**数据不丢**；个别读不出的文件保留在 `.broken-*` 中可通过 FTP 找回
- 后台「监控 → 环境自检 → **一键修复目录权限**」：对 data/ 全部关键目录执行完整自愈阶梯（建目录 → 修权限 → 整体搬移重建 → 重建空目录），修复后自动清理 `.broken-*` 暂存目录并回报告果
- 会话目录 `data/sessions/`、日志目录 `data/logs/`、备份目录 `data/backup/` 的创建全部改走自愈阶梯（此前为裸 mkdir，属主异常时静默失败）
- 修复日志目录不可写时 `log_action` 的未定义变量警告
- 安装向导：补齐 `data/sessions/`、`data/backup/` 目录初始化；关键目录逐个真实写探针，不可写在安装阶段即给出明确警告
- 报错文案统一给出可操作指引：先点后台一键修复，无效再通过 FTP 将 `data/` 及其子目录权限设为 755 / 775

### 修复（监控页渲染）

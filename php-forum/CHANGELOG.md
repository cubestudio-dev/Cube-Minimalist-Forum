# 更新日志 · Cube Minimalist Forum

## v1.6.0（2026-10-04）

### 新增（安全防护）
- **绑定域名（限制特定域名访问）**：后台「基本」新增「绑定域名（授权域名）」设置。**留空不限制（默认，行为与旧版完全一致）**；填写后仅允许列表内的域名访问论坛，其他域名（他人恶意解析到你主机 IP 的域名、镜像站、IP 直连）一律 **301 永久跳转**到第一个授权域名，原路径原样保留——搜索引擎权重自动归拢到正版域名，镜像站不再被收录
  - 多域名支持：逗号分隔（中文逗号 / 分号 / 空白同样兼容）；带 www 与不带 www 视为两个域名，需分别填写
  - 容错清洗：误填 `https://forum.com:8080/` 这类带协议头 / 端口 / 路径的写法，保存时自动规范化为 `forum.com`
  - 防锁死：配置保存在 `data/config.php`，万一域名写错导致访问异常，通过 FTP 删掉 `bind_domains` 一行即可恢复（后台设置页也附有说明）
  - 细节守卫：命令行环境（php -l、脚本）自动跳过；HTTPS / 反代场景自动识别协议；跳转目标强制本站路径，无开放重定向风险

### 发布物变更
- **新增通用更新包**（`forum-update-any-to-1.6.0.zip`）：v1.1.0 及以上的**任意版本**均可直接上传这一个包升级到 v1.6.0，无需逐版本中间升级。更新器本就只要求目标版本高于当前版本（来源版本不限），通用包内置全部程序文件 + 幂等迁移（自动补齐各版本新增配置项、不覆盖已有配置，可重复上传）；旧式按版本链的专用升级包自此由通用包取代

## v1.4.1（2026-10-04）

### 修复（监控页「纯黑色圆形」专项）
- **监控页环形进度渲染成一团黑色实心圆**：SVG 圆形的默认填充色是黑色，此前「不填充」完全依赖样式表中的 `.ring-bg/.ring-fg { fill:none }` 规则；而样式表引用地址不带版本号，浏览器会长期使用缓存的旧文件——升级程序后一旦样式表还是旧缓存（或 FTP 覆盖时未更新成功），环形就会退化成纯黑色圆形。现 `fill="none"` 直接内联进 SVG 标签（内联属性优先级低于样式表，主题色与深色模式不受任何影响），**无论样式表新旧都不会再出现黑圆**；同时样式表与脚本引用统一加版本号参数（`?v=版本号`），升级后浏览器立即拉取新资源，杜绝各类「升级后样式错乱」
- 后台「系统」页「有回复的帖」统计口径修正：此前数的是 `threads/` 目录文件数（等于帖子总数），现与监控页同口径——统计索引中回复数 > 0 的帖子

### 修复（个人主页帖子数与列表不符）
- **个人主页显示「发了 N 个帖子」，下方列表却是空的**：帖子数此前读用户档案里的计数器字段，该计数在历史版本静默写失败（发帖「假成功」）或删帖边界场景下会虚高。现帖子数改为**直接读取数据资源**（`threads/index.php` 帖子索引）实时统计，与下方「TA 的帖子」列表完全同源，数字与列表永远一致

## v1.4.0（2026-10-04）

### 修复（发帖失败专项 · 目录自愈能力升级）
- **「目录不可写」自愈能力升级——整体搬移重建**：通过 FTP / 主机面板解压或上传产生的数据子目录（如 `data/threads/`），属主往往不属于 PHP 运行账号；当目录非空时（帖子索引就在里面），此前 `chmod`（非属主失败）与「空目录重建」（非空失败）都无法救回，表现为发帖报「threads/index.php：目录不可写」。现利用 POSIX `rename` 只依赖**父目录**写权限的特性：把旧目录整体改名为 `data/.broken-xxx` 让位 → 原位重建属主正确的目录 → 将旧目录内文件逐个读出写回，**数据不丢**；个别读不出的文件保留在 `.broken-*` 中可通过 FTP 找回
- 后台「监控 → 环境自检 → **一键修复目录权限**」：对 data/ 全部关键目录执行完整自愈阶梯（建目录 → 修权限 → 整体搬移重建 → 重建空目录），修复后自动清理 `.broken-*` 暂存目录并回报告果
- 会话目录 `data/sessions/`、日志目录 `data/logs/`、备份目录 `data/backup/` 的创建全部改走自愈阶梯（此前为裸 mkdir，属主异常时静默失败）
- 修复日志目录不可写时 `log_action` 的未定义变量警告
- 安装向导：补齐 `data/sessions/`、`data/backup/` 目录初始化；关键目录逐个真实写探针，不可写在安装阶段即给出明确警告
- 报错文案统一给出可操作指引：先点后台一键修复，无效再通过 FTP 将 `data/` 及其子目录权限设为 755 / 775

### 修复（监控页渲染）
- **主机限制 /proc 时监控页不再渲染异常**：内存 / CPU 读数不可用时环形进度显示灰色虚线「当前环境不可读」状态（缓慢旋转示意，视觉上有意为之而非损坏），数值显示「—」，不再出现残缺文案（如孤立的「%」）或满圈异常颜色
- CPU：`/proc` 被主机限制时自动按系统负载估算（`load1 / 核心数`），脚注标注「主机限制 /proc · 按 N 核负载估算」；完全不可用时显示「—」
- 内存：`/proc` 被限制时显示本 PHP 进程占用与 `memory_limit` 上限

### 新增
- **监控页刷新间隔可自定义**：后台「监控 → 监控与告警设置」新增「监控页实时刷新间隔（秒，0=关闭）」，默认 5 秒、可选 0～300 秒（0 为关闭以节省流量；1 归一为 2 避免过于频繁）

## v1.3.0（2026-10-04）

### 修复（发帖失败专项）
- **发帖 / 回复在异常环境下静默失败**：此前 `data/` 目录不可写（虚拟主机权限不足、磁盘写满）或写入中途出错时，帖子索引写失败不报错，用户被跳到不存在的帖子页，表现为"无法发帖"。现存储层记录每次写失败原因，发帖 / 回复失败时**明确提示原因与修复方法**（如将 `data/` 目录权限设为 755），不再静默丢内容
- 帖子索引已写入但正文写失败时自动**回滚索引**，杜绝"索引有但打不开"的幽灵帖
- 全部业务动作套上**异常闸口**：任何服务器错误都会变成可读提示并记入操作日志（动作"系统·操作异常"），不再白屏无反馈
- **环境警告**：`data/` 不可写时页面对管理员持续显示醒目警告与修复指引
- 回跳字段（back）校验收紧 + 跳转强制剥离换行符：杜绝 Location 头注入（响应拆分）风险
- 开启页面访问日志时，AJAX 轮询与业务动作不再被记为"浏览页面"（防日志灌水）

### 新增（实时刷新）
- **前台实时刷新**：按后台可配间隔（默认 20 秒，可调 0-300 秒，0=关闭）自动更新
  - 侧栏「N 人在线」实时刷新；公告未读红点实时出现 / 消失
  - 首页 / 板块页有新帖或新回复时，顶部滑入"有新内容 · 点击刷新查看"提示条
  - 帖子页有新回复时，提示"有新回复 · 点击刷新查看"
  - **流量友好**：只读 JSON 轻量接口；页面切到后台标签页自动暂停轮询，回到前台立即刷新
- **后台「监控」页实时资源卡（动态图标）**
  - CPU 使用率：芯片图标核心脉冲动画 + 实时环形进度（读 /proc 采样，约 0.2 秒窗口）+ 系统负载
  - 内存使用率：内存条图标滑动填充动画 + 实时环形进度（MemTotal / MemAvailable）
  - 磁盘使用率：盘片旋转动画 + 实时环形进度 + 剩余 / 总量
  - 每 5 秒自动刷新读数（管理员专用接口，页面隐藏时暂停）；读数分三级变色（正常 / ≥60% 琥珀 / ≥85% 红）
- **环境自检卡**：data/ 与 sessions/ 可写性、flock / json / mail / curl / mbstring 等关键函数可用性一目了然；error.log 有内容时可在后台直接展开查看最近 12 行，配合异常闸口快速定位主机环境问题

### 加固
- 会话文件自动清理：部分主机 PHP 自带垃圾回收被关闭导致 `data/sessions/` 无限增长侵蚀存储配额；现随访问每小时清理 30 天未活跃的会话文件（记入日志"系统·自动清理"）
- 写入兼容 Windows 主机（rename 覆盖已存在文件前先删除）

## v1.2.0（2026-10-03）

### 修复
- **移动端整站变灰不可操作**：小屏下侧栏遮罩的 CSS `display:block` 覆盖了 `hidden` 属性的默认行为，导致遮罩常驻；现强制 `.side-mask[hidden]{display:none!important}`，遮罩只在打开侧栏时显示
- **在线人数不准**：登录时会话重造导致同一人被计 2 次；爬虫 / 不回传 Cookie 的客户端每次请求都算 1 人。现登录用户按账号去重（同账号多端只算 1 人）、过滤爬虫与空 UA，统计口径与「N 人在线」标签一致
- 验证码发送增加会话级 60 秒限频（与邮箱级限频双重防护，防止轮换邮箱滥用发信接口）
- 同一内容已有待审举报时拒绝重复举报（防止刷 AI 队列 / 反复隐藏内容）
- 回复被拒（锁帖）时不再白扣发言间隔（先校验后占用）
- 后台搜索不再硬依赖 mbstring 扩展（自动回退）
- 安装时自动写入 `data/.htaccess`（交付包不含 data 目录时补齐 Apache 保护）

### 新增
- **后台「监控」标签页（服务器性能监控）**
  - 存储占用进度条：程序本体 + 数据目录 / 配额（默认 100MB）
  - 服务器信息：PHP 版本与 SAPI、系统负载（1/5/15 分钟）、磁盘剩余、内存 / 执行时间 / 上传限制、curl 与 mbstring 可用性
  - 内容规模：帖子 / 有回复的帖 / 用户 / 日志体积 / 备份数 / 当前在线
  - **存储告警**：总占用超过阈值（默认 95MB）自动给全部管理员发告警邮件（含占用明细与清理建议）；随访问每小时检查一次，持续超限每 6 小时提醒一次，回落自动重置；支持手动测试告警
- **页脚自定义**：后台「主题」页可配置页脚文字（左）与备注（右），留空恢复默认；版本号自动同步

### 变更
- 论坛名称更名 **Cube Minimalist Forum**（安装向导 / 默认页脚 / 文档同步更新）
- 后台增至 15 个标签页
